# `postprocess-recording`

Runs the full offline post-processing pipeline for one recording. Lives in the
[`spotlight-tools`](https://github.com/NeLy-EPFL/spotlight-tools) repo
(`src/spotlight_tools/cli/postprocess_recording.py`). Output is written to a new
`processed/` subfolder under the recording directory.

The pipeline:

1. **Interpolates stage positions** at each behavior-frame timestamp (stage
   positions are logged at a lower rate than behavior frames).
2. **Unpacks the behavior frames** and merges them into a single H.264 video. During
   recording, frames are saved as *pseudo-BGR* JPEGs — each file packs three
   consecutive frames into the three color channels, a recording-time trade-off
   between compactness and speed. Per-frame timestamps are likewise written as many
   small files (to avoid cross-thread write contention) and merged here into a
   single CSV.
3. **Aligns the fly** (when `--align-fly`, the default): runs a 3-keypoint SLEAP pose
   estimate, then rotates/crops each frame so the fly faces up and is centered.
4. **Warps muscle frames** to the behavior frames (when `--with-muscle`) and applies
   the same alignment, for pixel-wise correspondence.
5. **Generates a summary video** (and, with muscle, overlay samples) for inspection.

## Usage

```bash
postprocess-recording --recording-dir <save_dir>/
```

Key options (run `postprocess-recording --help` for the complete list — the CLI is
generated by `tyro` from the function signature, so every parameter is a `--flag`;
booleans take a `--flag` / `--no-flag` form):

| Option | Default | Description |
|---|---|---|
| `--recording-dir PATH` | *(required)* | Recording root (the path set in the GUI). |
| `--overwrite` / `--no-overwrite` | `--no-overwrite` | Overwrite existing outputs instead of raising. |
| `--align-fly` / `--no-align-fly` | `--align-fly` | Run SLEAP pose estimation and align/crop frames to the fly. |
| `--with-muscle` / `--no-with-muscle` | `--no-with-muscle` | Also process and warp muscle frames. |
| `--make-visualizations` / `--no-...` | `--make-visualizations` | Generate the summary video and overlays. |
| `--crop-dim INT` | 900 | Output frame size (px) for aligned frames. |
| `--play-fps INT` | 33 | Playback FPS for the videos (display only; real FPS is fixed at recording time). |
| `--behavior-video-crf INT` | 12 | H.264 CRF for the behavior video (lower = higher quality; 12–17 ~ visually lossless). |
| `--behavior-video-preset STR` | `slow` | H.264 speed/compression preset for the behavior video. |
| `--visualization-crf INT` | 20 | H.264 CRF for the summary video. |
| `--visualization-preset STR` | `slow` | H.264 preset for the summary video. |
| `--num-workers INT` | -1 | Parallel workers (-1 = all cores). |
| `--log-level STR` | `INFO` | `DEBUG`/`INFO`/`WARNING`/`ERROR`/`CRITICAL`. |

(Other options control SLEAP batch size, muscle visualization range and sample
count, missing-muscle-frame tolerance, shared-memory scratch, and homography use.)
See https://trac.ffmpeg.org/wiki/Encode/H.264 for the CRF/preset parameters.

> [!NOTE]
> Muscle-frame warping (`--with-muscle`, and the `--use-homography` option) depends
> on a muscle-to-behavior calibration that is being moved to a separate
> [camera homography](../configuration/camera_homography.md) step (*TODO*).
