# Profiles and arenas

Spotlight separates settings into two directory types: **profiles** and **arenas**.
Both are passed to the recorder programs via command-line flags.

- Profile (`-p` / `--profile-dir`) — machine-specific settings independent of which
  arena is mounted: camera configuration, stage serial numbers, motion limits, GUI
  layout, and the muscle-camera ROI. **Required by every recorder program.**
- Arena (`-a` / `--arena`) — the physical description of a specific arena and its
  fitted registration model. Re-used across many recordings as long as the physical
  arena is unchanged. Required by `run-spotlight` and `run-arena-registration-scan`
  (not by `align-cameras`).

```bash
./run-spotlight               -p ~/Spotlight/profiles/default -a ~/Spotlight/arenas/arena146
./run-arena-registration-scan -p ~/Spotlight/profiles/default -a ~/Spotlight/arenas/arena146
./align-cameras               -p ~/Spotlight/profiles/default
```

## Profile directory

Profiles live under `~/Spotlight/profiles/`. A typical profile:

```
~/Spotlight/profiles/default/
│
│ # ===== Recorder configuration (created manually) =====
├── recorder_config.yaml     # camera/stage/tracking/GUI settings
│
│ # ===== File generated by align-cameras (muscle imaging only) =====
└── muscle_camera_roi.yaml   # how the muscle image is cropped to align with the
                             # behavior field of view
```

- `recorder_config.yaml` is the single source of machine settings. An annotated
  example ships at `recorder/etc/profile_example/recorder_config.yaml` — copy and
  edit it. It groups settings under `behavior_camera`, `muscle_camera`,
  `motion_control`, `tracking`, `triggering`, and `gui`. The stage serial numbers
  (`motion_control/stage_serial_no_x_axis`, `…_y_axis`) and the device
  manufacturer/description fields in particular are machine-specific.
- `muscle_camera_roi.yaml` is generated by [`align-cameras`](../recorder/align_cameras.md)
  and only needed when muscle imaging. It records the cropped ROI within the muscle
  sensor that aligns the two cameras' fields of view.

## Arena directory

Arenas live under `~/Spotlight/arenas/`. The directory is populated in stages by
different tools:

```
~/Spotlight/arenas/arena146/      # base directory for arena specs
│
│ # ===== Arena definition (PDF generated manually) =====
├── arena146_spec.pdf             # source-of-truth arena drawing (from CAD)
│
│ # ===== Generated by scripts/arena/make_arena146_config.py (spotlight-tools) =====
├── metadata.yaml                 # marker positions, arena dims, checksum, etc.
├── mapping_board.pdf             # printable board with AprilTag markers + DataMatrix
├── active_area.png               # rasterised active-area mask (0=wall, 255=accessible)
│
│ # ===== Collected by run-arena-registration-scan =====
├── mapping_scan/
│   ├── apriltag<id>_img<i>.jpg            # AprilTag images from the behavior camera
│   └── apriltag_stage_positions.csv       # stage positions when images were taken
│
│ # ===== Generated by fit-arena-registration =====
└── model/
    ├── calibration_points.csv    # pixel coordinates of detected AprilTag corners
    ├── calibration_result.yaml   # fitted transform between coordinate systems
    ├── detections/               # debug images showing AprilTag detections
    └── diagnostics.png           # diagnostic plot of the fitted model
```

> [!NOTE]
> The arena directory must contain a valid `model/calibration_result.yaml` before
> `run-spotlight` will start. Complete the registration scan and model fit first —
> see [Arena registration](arena_registration.md).

## Setting up a new arena directory

### Step 1 — Create the arena spec PDF

Design the arena in CAD and/or Illustrator/Inkscape/etc. and export a PDF that
encodes the marker geometry using colored shapes:

- **Red (#ff0000) squares** → AprilTag positions (sorted by shortest-path traversal
  from the DataMatrix).
- **Green (#00ff00) square** → DataMatrix position.
- **Black (#000000) shapes** → active-area / maze walls.

The red and green boxes should be squares. For **arena146**, pre-generated assets
are already bundled with `spotlight-tools` — skip to Step 2, Option A.

### Step 2 — Generate the arena config assets

The arena directory needs three derived files before the registration scan:
`metadata.yaml`, `mapping_board.pdf`, and `active_area.png`.

**Option A — Copy pre-generated assets (arena146 only):**

```bash
cp -r <spotlight-tools>/src/spotlight_tools/assets/arena_configs/arena146/* \
      ~/Spotlight/arenas/arena146/
```

**Option B — Regenerate from the spec PDF:**

```bash
cd spotlight-tools/
python scripts/arena/make_arena146_config.py
```

This runs `ArenaConfig` (`spotlight_tools.arena.arena`), which reads the spec PDF
with pymupdf and writes all three assets in place.

> [!NOTE]
> The DataMatrix barcode in `mapping_board.pdf` carries an 8-character hex checksum
> derived from all marker positions and the active-area bitmap.
> `run-arena-registration-scan` decodes this barcode at startup to verify the
> correct board is mounted before the scan begins.

### Step 3 — Print the mapping board

Print `mapping_board.pdf` at **100% scale** (no fit-to-page scaling). Cut to the
arena boundary (a thin cut-border is drawn 1 mm inside the page edge). Place the
board in the arena with the printed side facing the camera.

### Step 4 — Run the registration scan and fit the model

With the printed board in place, proceed to [Arena registration](arena_registration.md).
